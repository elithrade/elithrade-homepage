# elithrade-homepage

[![CI](https://github.com/elithrade/elithrade-homepage/actions/workflows/ci.yml/badge.svg)](https://github.com/elithrade/elithrade-homepage/actions/workflows/ci.yml)
[![E2E Test](https://github.com/elithrade/elithrade-homepage/actions/workflows/e2e.yml/badge.svg)](https://github.com/elithrade/elithrade-homepage/actions/workflows/e2e.yml)

Personal homepage of Bin Hu: a small Next.js site with three animated 3D cube pets,
light/dark themes, a bio and skills page, and a works page built from the CV.

**Live:** https://mango-pebble-00502641e.3.azurestaticapps.net

## Tech stack

- [TypeScript](https://www.typescriptlang.org) 6.0 in strict mode
- [Next.js](https://nextjs.org) 16 (pages router, Turbopack) and React 19
- [Chakra UI](https://v2.chakra-ui.com) 2 and Emotion for styling and colour mode
- [framer-motion](https://motion.dev) for page and section transitions
- [three.js](https://threejs.org) for the cube pets (`public/models/`), from
  Kenney's [Cube Pets](https://kenney.nl/assets/cube-pets) pack (CC0)
- [Vitest](https://vitest.dev) and Testing Library for unit tests
- [Playwright](https://playwright.dev) for end-to-end tests
- ESLint 10 (flat config) and Prettier

## Getting started

Requires Node.js 24 and npm.

```sh
npm ci
npm run dev
```

Then open http://localhost:3000. The dev server listens on `0.0.0.0`, so other
devices on your network can reach it too.

## Project structure

```
components/          UI components (navbar, theme toggle, cube pets, ...)
  layouts/           Page layouts: main shell and animated article wrapper
e2e/                 Playwright end-to-end tests
libs/
  model.ts           GLTF loader helper for the cube pets
  pets.ts            Which pets stand in the row, and where
  theme.ts           Chakra theme: colours, fonts, colour mode
  works.ts           Projects shown on /works, taken from the CV
pages/               Next.js routes (/, /works and /works/[id])
public/              Static assets: pet models (models/), images

```

## TypeScript

- `tsconfig.json` uses `strict` mode. Run `npm run typecheck` to check the
  whole project; `next build` also type-checks.
- TypeScript is pinned to 6.0.x because typescript-eslint, used by
  `npm run lint`, supports only TypeScript versions below 6.1.
- `next-env.d.ts` is generated by Next.js and gitignored.
  `npm run typecheck` regenerates it with `next typegen`.
- `types/legacy-html-attributes.d.ts` declares the old HTML attributes
  `align`, `justify` and `wrap`, which some components pass to Chakra `Box` and
  `Container`. Chakra forwards them to the DOM, and the layout depends on
  them: `align="center"` centres a block's contents.

## Dependencies

`package.json` has an `overrides` block for the ESLint toolchain:

- **ESLint 10 peer ranges.** `eslint-config-next` pulls in
  `eslint-plugin-react`, `eslint-plugin-jsx-a11y` and `eslint-plugin-import`,
  whose latest releases declare support only up to ESLint 9. They work with
  ESLint 10, so the overrides point their `eslint` peer at the project's
  version (`$eslint`) instead of printing peer warnings. ESLint 9 isn't an
  option: it's end-of-life and npm flags it as deprecated. Remove these
  overrides once the plugins declare ESLint 10 support.
- **minimatch.** ESLint, `@eslint/config-array` and
  `@typescript-eslint/typescript-estree` are moved to `minimatch` 11, which
  fixes [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).

### Known audit warning

`npm install` reports 5 moderate vulnerabilities. They're all the same
advisory: the three plugins above still depend on `minimatch` 3. There's no
patched 3.x release, and `minimatch` 11 drops the callable API those plugins
use, so it can't be overridden. The risk is accepted because:

- the packages are dev-only lint tooling and never reach the deployed site
- the issue is a denial of service through crafted glob patterns, and the only
  patterns these plugins see come from this repo's lint config

It clears once the plugins upgrade `minimatch`; check with `npm audit`.

## Theme

Colours are defined once, in `palette` in `libs/theme.ts`, and exposed as
Chakra semantic tokens (`surface`, `text-muted`, `accent`, ...) that switch
with the colour mode. The accent matches the theme toggle: purple in light
mode, amber in dark. A unit test checks that every text/background pair meets
WCAG AA contrast. Fonts are self-hosted with `next/font`
(`components/fonts.tsx`): Inter for text, M PLUS Rounded 1c for the wordmark.

## Adding a work

Works live in `libs/works.ts`. Add an entry to `works` with a unique,
URL-safe `id`; the list page groups it under its organisation and
`/works/<id>` is generated at build time. The unit and e2e tests pick up new
entries automatically.

## Testing

### Unit tests

Unit tests use Vitest with jsdom and `@testing-library/react`.

- Component and library tests sit next to the code they test, as
  `*.test.ts` or `*.test.tsx` (for example `libs/model.test.ts`).
- Page tests live in `test/pages/`. Next.js turns every file in `pages/`
  into a route, so tests can't go there.
- Render components with `renderWithTheme` from `test/test-utils.tsx`, which
  wraps them in the Chakra provider and site theme.
- `test/setup.ts` loads jest-dom matchers, polyfills `matchMedia` and turns
  off framer-motion animations.

### End-to-end tests

The Playwright tests in `e2e/` run in Chromium against a production build
served with `next start` on port 3100. They cover:

- home page content
- the works list and every work's detail page
- the cube pets loading and rendering
- the theme toggle, including persistence across reloads
- navigation and the 404 page
- the mobile menu

```sh
npx playwright install --with-deps chromium   # first time only
npm run test:e2e
```

`npm run test:e2e` builds the app first. To test a build you already have,
set `E2E_SKIP_BUILD=1`. Locally, Playwright reuses a server already running
on port 3100.

Import `test` and `expect` from `e2e/fixtures.ts`, not from
`@playwright/test`. The fixture fails a test on any uncaught page error,
console error or HTTP 4xx/5xx response. If a test expects one, allow it with
`test.use({ allowedErrors: [/pattern/] })`.

If Chromium can't run on your machine (for example WSL without its system
libraries), run the tests in the Playwright Docker image:

```sh
docker run --rm --ipc=host --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v "$PWD:$PWD" -w "$PWD" mcr.microsoft.com/playwright:v1.64.1-noble \
  npm run test:e2e
```

## CI/CD

- **CI** (`.github/workflows/ci.yml`): on every pull request to `main` and
  every push to it, runs `npm ci`, `npm run lint` and `npm test`. `main` is
  protected: the `test` check must pass before a PR can merge.
- **E2E Test** (`.github/workflows/e2e.yml`): a separate workflow that runs
  the Playwright suite against a production build on every pull request to
  `main`, every push to it, and on demand from the Actions tab. The HTML
  report and failure traces are uploaded as the `playwright-report`
  artifact.
- **Deploy** (`.github/workflows/azure-static-web-apps-*.yml`): Azure Static
  Web Apps builds and deploys every push to `main`. Each pull request gets
  its own preview environment, which is removed when the PR closes.
